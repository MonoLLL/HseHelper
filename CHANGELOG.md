# Changelog

Все заметные изменения, внесенные в проект в рамках текущей доработки.

## [Unreleased]

### Added
- Добавлен `CHANGELOG.md` для фиксации доработок проекта.
- Добавлена поддержка накопления нескольких файлов в пользовательской форме на главной странице сайта.
- Добавлена поддержка накопления нескольких файлов в админской форме ответа на обращение.
- Добавлен визуальный список выбранных файлов с возможностью удалить отдельное вложение до отправки.
- Добавлен watcher-режим для Telegram-бота через `watchfiles`.
- Добавлен модуль [backend/app/admin_setup.py](backend/app/admin_setup.py) для автоматического создания первого администратора из переменных окружения.
- Добавлены env-переменные:
  - `DEFAULT_ADMIN_EMAIL`
  - `DEFAULT_ADMIN_PASSWORD`
  - `DEFAULT_ADMIN_NAME`
- Добавлена единая функция сериализации входящих обращений `incoming_to_out()` в [backend/app/routers/incoming.py](backend/app/routers/incoming.py).
- Добавлены строгие типы для обращений:
  - `IncomingChannel = "bot" | "site"`
  - `IncomingStatus = "new" | "in_progress" | "done"`
- Добавлена обработка `401` в админском интерфейсе с автоматическим logout и возвратом на форму входа.
- Добавлен флаг `authReady` в админке для исключения лишнего визуального скачка при первом рендере.

### Changed
- Исправлена работа загрузки нескольких файлов на стороне студента в [frontend/pages/index.jsx](frontend/pages/index.jsx).
- Исправлена работа загрузки нескольких файлов на стороне администратора в [frontend/pages/admin/index.jsx](frontend/pages/admin/index.jsx).
- Убрана системная надпись `файл не выбран` у file input в интерфейсе студента и администратора.
- Настроен dev-режим Docker без постоянной пересборки:
  - frontend переведен на bind mount
  - включен polling для слежения за файлами в Docker на Windows
  - bot запускается через watcher
- Исправлена отправка обращения со страницы FAQ:
  - вместо JSON используется `FormData`
  - добавляется `client_id`
- Значение `channel` для обращений из Telegram-бота изменено с `telegram` на `bot`.
- Статусы обращений приведены к единому виду:
  - frontend страницы "Мои обращения" теперь использует `done` вместо `answered`
- Логин админки переведен на нормальный `POST` с form body вместо передачи логина и пароля через query string.
- Форма входа в админку больше не подставляет пароль по умолчанию.
- Логика создания первого администратора вынесена из роутера в startup приложения.
- Startup-инициализация приложения перенесена в [backend/app/main.py](backend/app/main.py).
- Инициализация `FastAPI` в [backend/app/main.py](backend/app/main.py) очищена от дублирования.
- В backend подключен health endpoint.
- `answered_at` теперь выставляется только когда:
  - статус обращения `done`
  - текст ответа не пустой
  В остальных случаях поле сбрасывается.

### Fixed
- Исправлен баг, при котором выбор новой пачки файлов затирал уже выбранные вложения.
- Исправлен баг, при котором нельзя было удобно работать с несколькими файлами в форме сайта.
- Исправлен баг, при котором нельзя было удобно работать с несколькими файлами в форме администратора.
- Исправлен баг на странице FAQ, где отправка обращения могла ломаться из-за несовпадения формата запроса с backend API.
- Исправлен баг в admin API: `model_dict()` заменен на корректный `model_dump()`.
- Исправлена проверка доступа в admin API:
  - раньше проверялось только наличие `Bearer`
  - теперь токен реально декодируется и валидируется
- Исправлена несогласованность между frontend и backend по статусу ответа на обращение.
- Исправлена несогласованность между bot и backend по значению канала обращения.
- Исправлен logout в админке:
  - очищает токен
  - возвращает интерфейс в режим логина
  - не вызывает падение React из-за передачи объекта события в `setErr`
- Исправлена работа админки при истекшей сессии: вместо зависания пользователь корректно разлогинивается.
- Исправлены и очищены дублирующиеся импорты и части startup-логики.

### Security
- Усилена проверка JWT в admin API.
- Убран небезопасный публичный сценарий создания первого администратора как основной поток работы.
- Создание первого администратора переведено на controlled startup initialization через `.env`.
- Пароль администратора больше не передается в URL при логине.

### Developer Experience
- Frontend теперь подхватывает локальные изменения через Docker volume.
- Bot теперь перезапускается автоматически при изменениях исходников.
- Backend по-прежнему работает с `uvicorn --reload`.
- Добавлена единая точка инициализации default admin для более предсказуемого локального запуска.

## Notes

### Текущие данные администратора по умолчанию
Если не менялись значения в `.env`, используются:

- `DEFAULT_ADMIN_EMAIL=admin@uni.local`
- `DEFAULT_ADMIN_PASSWORD=admin123`
- `DEFAULT_ADMIN_NAME=Admin`

### После изменения backend-логики
Рекомендуется перезапуск backend-контейнера:

```powershell
docker compose restart backend
```
